# ADR 0002: Job Lifecycle and Multi-Service Data Boundaries

## Status
Accepted

## Context
Parity 2.5 ต้องรองรับงาน 3 แบบ: ซ่อมคอมพิวเตอร์ (`REPAIR`), งานโปรเจกต์ออนไลน์ (`PROJECT`), และงานบริการรายเดือน (`RETAINER`) โดยต้องการขอบเขตข้อมูลที่ชัดเจน และไม่สร้างความซ้ำซ้อนหรือความยุ่งยากเกินจำเป็นสำหรับผู้ใช้งานคนเดียว

## Decisions
1. **Field Boundaries:**
   - `REPAIR`: มุ่งเน้นฮาร์ดแวร์ (อุปกรณ์, อาการ, อะไหล่, รูปถ่าย R2 สูงสุด 5 รูป)
   - `PROJECT`: มุ่งเน้นส่งมอบ (Scope, Deadline, URL เว็บ, ลิงก์งาน Google Drive/Docs)
   - `RETAINER`: มุ่งเน้นรอบบิล (URL เว็บ, วันตัดรอบบิล `billing_cycle_day`, ยอดรายเดือน)
2. **Retainer Lifecycle:**
   - งานรายเดือนใช้สถานะ `ACTIVE` เป็นหลัก ไม่สร้างใบงานซ้ำทุกเดือน แต่ใช้ระบบตรวจจับวันที่ของรอบบิลเพื่อแสดง Badge เตือนบน Dashboard
3. **Billing Simplicity:**
   - บันทึกการเงินแบบ Manual (ยอดรวม, มัดจำ, ยอดคงค้าง) และมีหน้า Digital Slip สำหรับแชร์ผ่าน LINE / พิมพ์ออกกระดาษ ไม่ใช้ Payment Gateway ในเฟสนี้

## Consequences
- โครงสร้างฐานข้อมูล D1 สะอาด เป็นระเบียบ
- ผู้ใช้เปิดจ็อบใหม่ได้เร็วโดยไม่ต้องกรอกฟิลด์ที่ไม่เกี่ยวกับงานประเภทนั้นๆ
